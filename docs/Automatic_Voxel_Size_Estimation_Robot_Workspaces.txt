Automatic Voxel-Grid Size Estimation for Intersecting Robot Workspaces
Prior approximation from raw XYZ workspace CSV files — without repeated
voxelization Technical note with formulas and TypeScript
implementation 1. Problem Statement Two robot working spaces are stored
as CSV point clouds. Every row represents a reachable Cartesian point p
= (x, y, z). A voxel grid is later used to identify the spatial overlap
between the two workspaces, i.e. candidate handover regions. A fixed
voxel size is undesirable: a small physical overlap may produce too few
common voxels with a coarse grid, whereas a large overlap may generate
an unnecessarily large number of intersection voxels with a very fine
grid. The requirement considered here is stronger than adaptive
multi-resolution voxelization: estimate a suitable voxel size before
constructing the voxel grid, using only the raw XYZ coordinates. 2. Why
Multiple Voxelizations Are Not Required A convergence-based strategy
(voxelize with s, s/2, s/4, … until the overlap stabilizes) is valid,
but it necessarily performs several voxelizations. For a prior
estimator, information already contained in the point clouds can be used
instead: local sample spacing tells us the useful spatial resolution of
the data; the geometric bounding boxes provide a very cheap first
overlap estimate; nearest-neighbor distances between the two point
clouds provide a much better estimate of the true overlap without
constructing voxels; the desired number of intersection voxels can then
be converted analytically into a voxel edge length. 3. Step 1 — Estimate
Native Point-Cloud Spacing For each point in workspace P, compute the
distance to its nearest different point. For point pᵢ: dᵢ = minⱼ≠ᵢ ‖pᵢ −
pⱼ‖₂ Use a robust statistic because occasional duplicate points,
singular configurations, or locally dense regions can distort a mean. A
median is a simple default: d_R1 = median({dᵢ | pᵢ ∈ P₁}), d_R2 =
median({dᵢ | pᵢ ∈ P₂}) d_eff = max(d_R1, d_R2) d_eff is a practical
lower useful scale: creating voxels far smaller than the more sparsely
sampled workspace normally creates resolution that is not supported by
the source data. If Cartesian point density varies strongly, for example
because the workspace was generated by regular sampling in joint space
rather than Cartesian space, use a higher robust percentile instead of
the median: d_eff = max(Q₀.₇₅(D_R1), Q₀.₇₅(D_R2)) Here Q₀.₇₅ denotes the
75th percentile of nearest-neighbor distances. 4. Step 2 — Very Cheap
Bounding-Box Pre-Estimate For each workspace, compute its axis-aligned
bounding box. For robot 1: B₁ = [x₁,min, x₁,max] × [y₁,min, y₁,max] ×
[z₁,min, z₁,max] The overlap length along x is: Lₓ = max(0, min(x₁,max,
x₂,max) − max(x₁,min, x₂,min)) Analogously obtain Lᵧ and L_z. The
bounding-box overlap volume is: V_bbox = Lₓ · Lᵧ · L_z For a desired
number N_target of intersection voxels, a first voxel-size estimate
follows from V ≈ N·s³: s_bbox ≈ ∛(V_bbox / N_target) s₀ = max(d_eff,
s_bbox) This is extremely cheap, but it can substantially overestimate
overlap for curved, shell-like, disconnected, or highly non-convex robot
workspaces. Therefore it is best treated as a fallback or initial scale
estimate, not as the preferred final prior estimator. 5. Step 3 —
KD-Tree Proximity Estimate of the Real Overlap A better prior estimate
uses the raw point coordinates directly. Build a KD-tree for P₂. For
each point pᵢ in P₁, query the distance to its nearest point in P₂:
δᵢ¹→² = min_{q ∈ P₂} ‖pᵢ − q‖₂ Treat pᵢ as belonging to a candidate
common region when its nearest point in the other workspace is within a
proximity radius r. A simple radius is tied to the sampling scale: r = κ
· d_eff, with κ ≈ 1 … 1.5 Count the candidate points: N_close = |{pᵢ ∈
P₁ : δᵢ¹→² ≤ r}| Under approximately uniform volumetric sampling, one
raw point represents a characteristic spatial volume proportional to
d_eff³. Thus: V̂_intersection ≈ N_close · d_eff³ Demanding approximately
N_target occupied intersection voxels yields: N_target ≈ V̂_intersection
/ s³ s_est ≈ d_eff · ∛(N_close / N_target) Finally impose the
sampling-resolution lower bound: s_voxel = max(d_eff, s_est) 6. Optional
Improvements to the Prior Estimate Bidirectional proximity: repeat the
query P₂ → P₁. This reduces bias when one CSV is much denser than the
other. Subsampling: estimate spacing and overlap using a random subset
(e.g. 5–20% of points), then scale the close-point count by the sampling
fraction. This can make the pre-estimation very fast. Robust spacing:
use the 75th percentile of nearest-neighbor spacing when Cartesian
sampling is non-uniform. Clamp voxel size: define engineering limits
s_min and s_max from robot accuracy, object size, handover tolerance,
and memory constraints. Minimum physical resolution: if the robot
positioning uncertainty is ±ε, a voxel size much smaller than ε may be
misleading even if the point cloud is dense. A useful clamped result is
therefore: s_final = clamp(max(d_eff, s_est), s_min, s_max) 7. Shared
Voxel-Grid Origin Is Mandatory When the final voxelization is executed,
both workspaces must use the same grid origin. Otherwise equal voxel
indices do not refer to the same physical volume. Define a common origin
component-wise from both point clouds, for example: o = min(P₁ ∪ P₂)
(component-wise) Map a point p into voxel coordinates using: v(p) = ⌊(p
− o) / s_final⌋ The floor operation is applied independently to x, y,
and z. 8. Recommended Algorithm 1. Load both CSV files into arrays of
XYZ points. 2. Estimate nearest-neighbor spacing d_R1 and d_R2 from each
point cloud (preferably from a random sample). 3. Compute d_eff as the
maximum median or maximum 75th percentile spacing. 4. Build a KD-tree
for the second workspace and estimate N_close using radius r = κ·d_eff.
5. Optionally repeat in the reverse direction and combine the two
estimates. 6. Calculate s_est = d_eff·∛(N_close/N_target). 7. Apply
sampling, physical-accuracy, and user-defined minimum/maximum bounds. 8.
Perform the actual voxelization once using s_final and one shared grid
origin. 9. If the one-shot result is pathological (e.g. zero
intersection despite known overlap), fall back to one corrective
re-estimation rather than a full resolution sweep. 9. TypeScript
Implementation The following example uses the npm package
kd-tree-javascript for nearest-neighbor queries. CSV parsing is kept
dependency-light. Distances and coordinates must use the same units
(e.g. all millimetres or all metres). // npm install kd-tree-javascript
// npm install –save-dev @types/node

import { readFileSync } from “node:fs”; import { kdTree } from
“kd-tree-javascript”;

export interface Point3D { x: number; y: number; z: number; }

export interface VoxelEstimateOptions { targetIntersectionVoxels:
number; proximityFactor?: number; // kappa, default 1.25 sampleSize?:
number; // max points used per estimate spacingPercentile?: number; //
0.50 = median, 0.75 for non-uniform density minVoxelSize?: number;
maxVoxelSize?: number; bidirectional?: boolean; }

export interface VoxelEstimateResult { spacingRobot1: number;
spacingRobot2: number; effectiveSpacing: number; proximityRadius:
number; estimatedClosePoints: number; estimatedVoxelSize: number;
finalVoxelSize: number; } 9.1 CSV loading and basic utilities export
function loadXYZCsv( path: string, columns = { x: 0, y: 1, z: 2 },
hasHeader = true, ): Point3D[] { const lines = readFileSync(path,
“utf8”) .split(//) .filter(line => line.trim().length > 0);

const dataLines = hasHeader ? lines.slice(1) : lines; const points:
Point3D[] = [];

for (const line of dataLines) { const cells = line.split(/[;,/).map(v =>
v.trim()); const p = { x: Number(cells[columns.x]), y:
Number(cells[columns.y]), z: Number(cells[columns.z]), };

    if (Number.isFinite(p.x) && Number.isFinite(p.y) && Number.isFinite(p.z)) {
      points.push(p);
    }

}

return points; }

function euclidean(a: Point3D, b: Point3D): number { return
Math.hypot(a.x - b.x, a.y - b.y, a.z - b.z); }

function percentile(values: number[], q: number): number { if
(values.length === 0) throw new Error(“Empty value array”); const sorted
= […values].sort((a, b) => a - b); const pos = (sorted.length - 1) * q;
const lo = Math.floor(pos); const hi = Math.ceil(pos); if (lo === hi)
return sorted[lo]; const t = pos - lo; return sorted[lo] * (1 - t) +
sorted[hi] * t; }

function randomSample(items: T[], maxCount: number): T[] { if
(items.length <= maxCount) return […items]; const result = […items]; for
(let i = result.length - 1; i > 0; –i) { const j =
Math.floor(Math.random() * (i + 1)); [result[i], result[j]] =
[result[j], result[i]]; } return result.slice(0, maxCount); } 9.2
Estimate native sampling spacing function estimateSpacing( points:
Point3D[], sampleSize = 10_000, q = 0.50, ): number { if (points.length
< 2) throw new Error(“At least two points are required”);

const tree = new kdTree(points, euclidean, [“x”, “y”, “z”]); const
sample = randomSample(points, sampleSize); const nearestDistances:
number[] = [];

for (const p of sample) { // Ask for two neighbors because the nearest
one is normally p itself. const neighbors = tree.nearest(p, 2); const
nonZero = neighbors .map(([, distance]) => distance) .filter(distance =>
distance > 1e-12);

    if (nonZero.length > 0) nearestDistances.push(Math.min(...nonZero));

}

if (nearestDistances.length === 0) { throw new Error(“Could not estimate
non-zero nearest-neighbor spacing”); }

return percentile(nearestDistances, q); } 9.3 Estimate candidate overlap
without voxelization function estimateClosePointCount( source:
Point3D[], target: Point3D[], radius: number, sampleSize = 20_000, ):
number { const tree = new kdTree(target, euclidean, [“x”, “y”, “z”]);
const sample = randomSample(source, sampleSize); let closeInSample = 0;

for (const p of sample) { const nearest = tree.nearest(p, 1, radius); if
(nearest.length > 0 && nearest[0][1] <= radius) { closeInSample++; } }

const closeFraction = closeInSample / sample.length; return
closeFraction * source.length; } 9.4 One-shot voxel-size estimator
export function estimateVoxelSize( robot1: Point3D[], robot2: Point3D[],
options: VoxelEstimateOptions, ): VoxelEstimateResult { const {
targetIntersectionVoxels, proximityFactor = 1.25, sampleSize = 20_000,
spacingPercentile = 0.50, minVoxelSize = 0, maxVoxelSize =
Number.POSITIVE_INFINITY, bidirectional = true, } = options;

if (targetIntersectionVoxels <= 0) { throw new
Error(“targetIntersectionVoxels must be > 0”); }

const d1 = estimateSpacing(robot1, sampleSize, spacingPercentile); const
d2 = estimateSpacing(robot2, sampleSize, spacingPercentile); const dEff
= Math.max(d1, d2); const radius = proximityFactor * dEff;

const close12 = estimateClosePointCount(robot1, robot2, radius,
sampleSize); let closeEstimate = close12;

if (bidirectional) { const close21 = estimateClosePointCount(robot2,
robot1, radius, sampleSize);

    // Convert each directional result to an overlap fraction and use the
    // conservative smaller fraction. This reduces density-asymmetry bias.
    const f12 = close12 / robot1.length;
    const f21 = close21 / robot2.length;
    const f = Math.min(f12, f21);

    // Express the estimate in units of points at the more sparsely sampled set.
    closeEstimate = f * Math.min(robot1.length, robot2.length);

}

// Analytical estimate: s = d_eff * cbrt(N_close / N_target). // Do not
go below native sample spacing. const ratio = Math.max(closeEstimate /
targetIntersectionVoxels, 1); const sEst = dEff * Math.cbrt(ratio);

const lowerBound = Math.max(dEff, minVoxelSize); const finalSize =
Math.min(Math.max(sEst, lowerBound), maxVoxelSize);

return { spacingRobot1: d1, spacingRobot2: d2, effectiveSpacing: dEff,
proximityRadius: radius, estimatedClosePoints: closeEstimate,
estimatedVoxelSize: sEst, finalVoxelSize: finalSize, }; } 9.5 Example
usage const workspace1 = loadXYZCsv(“robot1.csv”); const workspace2 =
loadXYZCsv(“robot2.csv”);

const estimate = estimateVoxelSize(workspace1, workspace2, {
targetIntersectionVoxels: 1_000, proximityFactor: 1.25, sampleSize:
20_000, spacingPercentile: 0.75, // robust choice for non-uniform
Cartesian density minVoxelSize: 0, // set according to units / robot
accuracy if known maxVoxelSize: Infinity, bidirectional: true, });

console.log(estimate);
console.log(Recommended voxel edge length: ${estimate.finalVoxelSize});
10. Optional Bounding-Box Fallback in TypeScript interface Bounds3D {
min: Point3D; max: Point3D; }

function bounds(points: Point3D[]): Bounds3D { const xs = points.map(p
=> p.x); const ys = points.map(p => p.y); const zs = points.map(p =>
p.z); return { min: { x: Math.min(…xs), y: Math.min(…ys), z:
Math.min(…zs) }, max: { x: Math.max(…xs), y: Math.max(…ys), z:
Math.max(…zs) }, }; }

function bboxOverlapVolume(a: Bounds3D, b: Bounds3D): number { const lx
= Math.max(0, Math.min(a.max.x, b.max.x) - Math.max(a.min.x, b.min.x));
const ly = Math.max(0, Math.min(a.max.y, b.max.y) - Math.max(a.min.y,
b.min.y)); const lz = Math.max(0, Math.min(a.max.z, b.max.z) -
Math.max(a.min.z, b.min.z)); return lx * ly * lz; }

function bboxVoxelEstimate( p1: Point3D[], p2: Point3D[], targetVoxels:
number, effectiveSpacing: number, ): number { const volume =
bboxOverlapVolume(bounds(p1), bounds(p2)); if (volume <= 0) return
effectiveSpacing; return Math.max(effectiveSpacing, Math.cbrt(volume /
targetVoxels)); } 11. Important Assumptions and Limitations The
analytical N_close·d_eff³ model assumes that CSV points approximately
sample a 3-D volume. If the CSV contains only a workspace surface, the
cubic-volume model is not appropriate. If the point density changes
substantially across the workspace, a single d_eff is only a global
approximation. Local-density estimation (e.g. k-nearest-neighbor radius)
is more accurate but more complex. The proximity factor κ is an
engineering tolerance. κ = 1.0 is strict; 1.25–1.5 is more tolerant of
slightly shifted sample lattices. N_target should reflect the downstream
task. If the intersection points are used to optimize a handover point,
hundreds to a few thousand occupied voxels are often more useful than an
arbitrary fixed spatial resolution. A guaranteed “optimal” voxel size
cannot be derived from point coordinates alone without defining what
adequacy means. The estimator therefore needs a target such as desired
intersection voxel count, maximum geometric error, or handover-location
tolerance. If the two workspaces are expressed in different robot-local
coordinate systems, transform both into the same world/reference frame
before all distance, overlap, and voxel computations. 12. Recommended
Default Configuration 13. Final Recommendation For the described
robot-workspace problem, the preferred prior approximation is: estimate
native point spacing → estimate cross-workspace proximity with a KD-tree
→ analytically convert the estimated overlap population into one voxel
size → voxelize once. This satisfies the goal of avoiding a
trial-and-error sweep over multiple voxel sizes while still adapting
automatically to small and large workspace intersections. s_final =
clamp(max(d_eff, d_eff · ∛(N_close / N_target)), s_min, s_max) For
non-uniform workspace sampling, use the 75th percentile of
nearest-neighbor spacing and bidirectional proximity estimates. If later
experiments show that the handover optimum is sensitive to voxel
resolution, the target should be reformulated in terms of maximum
acceptable handover-position error rather than only the number of
intersection voxels. Recommended approach Estimate the native point
spacing of both workspace point clouds, estimate their possible overlap
using nearest-neighbor proximity (KD-tree), and analytically derive one
voxel size that should yield a desired number of occupied intersection
voxels. The actual voxelization can then be executed once. Parameter
Suggested default Reason spacingPercentile 0.50 (median) or 0.75 0.75 is
safer for variable Cartesian density. proximityFactor κ 1.25 Tolerates
small sampling-lattice offsets without being excessively permissive.
sampleSize 10,000–20,000 points Usually enough for stable robust
statistics while keeping KD-tree queries cheap. N_target ~500–2,000
Reasonable starting range for a handover candidate region; tune to
downstream optimizer. bidirectional true Reduces bias when point clouds
differ in density. s_min ≥ robot/measurement accuracy Avoids claiming
unsupported physical precision.
